# Z80 — 8-bit microprocessor (NMOS)

## Function

A processor: it reads a program from memory and runs it. Its work comes in machine cycles of three to six clock cycles (T-states) each: an opcode fetch, a memory read or write, an input or output, an interrupt acknowledge. Each starts on a rising edge of `CLK` with an address on `A0`–`A15`.

- An opcode fetch (`M1_N` low) reads with `MREQ_N` and `RD_N` low and takes the byte at the start of its third clock. For its last two clocks the address shows the refresh address, `I` in the high byte and the refresh counter `R` in the low, with `RFSH_N` low and `MREQ_N` pulsing low, so dynamic memory can refresh. `R` counts one for each opcode fetch.
- A memory read has `MREQ_N` and `RD_N` low, and a write `MREQ_N` and then `WR_N` low, with the data on `D0`–`D7`. An input or output has `IORQ_N` low with `RD_N` or `WR_N`, and one extra clock; the port number is on the address, with a register in the high byte.
- `WAIT_N` low, seen on the falling edge of a cycle's second clock, adds a clock, and another for each falling edge that still sees it low.
- `INT_N` low asks for an interrupt. It is looked at on the last clock of each instruction and taken if the program has enabled interrupts (`EI`), never straight after `EI`. The acknowledge is an opcode fetch with `IORQ_N` low in place of `MREQ_N`, and two extra clocks. Mode 0 runs the instruction that the device puts on the data bus, mode 1 calls `0038`, and mode 2 calls the address read from a table at `I` and the byte on the bus.
- `NMI_N` going low always gets an interrupt, after the current instruction: a call to `0066`.
- `HALT` stops the program. `HALT_N` goes low and the processor keeps fetching NOPs (refresh going on) until an interrupt or a reset.
- `BUSRQ_N` low asks for the bus. At the end of the current machine cycle the address, data, `MREQ_N`, `IORQ_N`, `RD_N` and `WR_N` float and `BUSAK_N` goes low, until `BUSRQ_N` goes high again.
- `RESET_N` low resets it: the address and data float and the control outputs go high. On release it starts at `0000`, interrupts off. At power-on its registers hold whatever they happen to; without a reset it runs from anywhere.
- Every opcode does something, the undocumented ones too.
- Its inputs are MOS: an input left floating keeps the level it last had.

## Pins

- `A0`–`A9`, `A10`–`A15`: address; `A0` is the lowest bit
- `D0`–`D7`: data, driven by the Z80 only while writing; `D0` is the lowest bit
- `CLK`: clock in, up to 4 MHz
- `M1_N`: low during an opcode fetch and an interrupt acknowledge
- `MREQ_N`: low while the address is a memory address (and during refresh)
- `IORQ_N`: low while the address is a port, and during an interrupt acknowledge
- `RD_N`: low while reading
- `WR_N`: low while the data pins hold data to write
- `RFSH_N`: low while the address holds the refresh address
- `HALT_N`: low while halted
- `WAIT_N`: low to make a memory or I/O cycle longer
- `INT_N`: interrupt request, low to ask
- `NMI_N`: non-maskable interrupt, on its falling edge
- `BUSRQ_N`: bus request, low to ask
- `BUSAK_N`: bus acknowledge, low while the bus is given away
- `RESET_N`: reset, low to reset
- `VCC`: +5 V
- `GND`: 0 V
