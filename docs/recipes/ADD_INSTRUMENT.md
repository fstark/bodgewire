# Recipe — Add an instrument

A measuring tool placed on the Board with a window (logic probe P2g, logic analyzer P3c, multimeter and scope P3d). Threads: sim → devices (Consumers) → UI ([ARCHITECTURE.md](../ARCHITECTURE.md)).

Reference commits (P3d, multimeter + scope): `ecb3915` placement + volts, `53327ba`/`1414e2b` engines, `7180f0c` consumers, `2bdcbe2` Session, `6c06d28` tool/window pairing, `94dd63b`/`d3388bf` windows. P5e (an instrument widened): `168402f` analyzer engine (32 Channels, mask Triggers, bus patterns), `ceaf4a0` scope delay, watch budget and Dispatcher merge, `7c45e1b` Channel Groups in the Session, `ddd0f7a` windows. P5f (windows made coherent): `d3759d1` time view maths, `2bf1bb3` analyzer window and flags, `f24ff06` scope window.

Tests in `tests/session/session_test.cpp` |

| Focus | `src/view/focus.{hpp,cpp}`, `src/ui/shelf.cpp`, `src/ui/shelf_drawings.cpp`, `src/ui/main.cpp` | an `Owner` (and its slot in `Focus::out_`), tested in `tests/view/focus_test.cpp`; an `Item` with its vector drawing (lit when out) on the shelf (no key: P6o); the click case in `main.cpp`'s switch on `focus.owner()`; `shelf.refused(reason)` and `boardView.refuse(reason)` for a click it cannot act on (P6c). | Window | `src/ui/<x>_window.{hpp,cpp}`, `src/ui/CMakeLists.txt`, `src/ui/main.cpp` | ImGui window, `bool draw(bool& open, Session&)` called from main's `instrument(owner, window)`: `BeginInstrument(name, open, BenchObject)` begins it under its name constant (`k<X>WindowName`, for the shelf's `BringToFront`/`InFront`), at its default place and normal size the first time it comes out, then where the player left it, with the minimal / normal button in its title bar (a `BenchObject` with its place and two sizes in `src/view/bench_places.cpp`, tested in `tests/view/bench_places_test.cpp`; P6d), `InstrumentClicked` returns a click (it then takes the focus), closing it puts it away; `PlaceNext` also keeps it on the bench or, popped out, gives it its own desktop window (a double-click on its shelf drawing, `TogglePop`, `--pop`, P6j, P6o); `PopOnDoubleClick(object)` last before its `End` does the same for a double-click on its title bar; no lead button, no gold (the gold is on its shelf drawing). ## Gotchas

- `kMaxWatched` = 96 watched Nets for devices + every instrument together. Rings are allocated, not written: an unused slot costs no memory. The Dispatcher merges Samples with a heap over the slots that hold some; never go back to scanning every slot or every Consumer's `nets()` per Sample (a 32-Clip bus is millions of Samples a second).
- A Net watched again gets no new Sample until it changes: implement `Consumer::seed` or it reads X.
- `configure()` while Off must set the UI-side phase directly (no slices arrive).
- `Runner::powerOff` is queued: `waitIdle()` before checking; `waitIdle` hangs if Running without `pauseAt`.
- Short tests: a Capture is 65 536 points: 655 µs at 100 MHz, 6.5 ms at 10 MHz, 65 ms at 1 MHz. Runner and Session tests use 100 MHz.
- Reading a bus in a Capture: take the data at the last point of the cycle with `PHI2` high, not the cycle's last point (the 6502 lets go of the data 40 ns before it changes the address; a floating bus with TTL inputs reads `FF`).
- Threads: run the session/runner tests under TSan (separate build dir with `-fsanitize=thread`).
- Release gate: 1.00× with every instrument attached on the busiest Machine, UI under ~1 ms (`bw_ui --screenshot` prints both).
- Every bench window goes through `PlaceNext` (or `OnBench` for one that never leaves the bench) before its `Begin`: with ImGui's multi-viewports on (P6j), a window left to ImGui becomes a desktop window when dragged past the main window's edge. `TogglePop` takes the window's name (its last place and size).
- `PlaceNext` puts a window at its default place and first size the first time it comes out (`FirstUseEver`); after that both are the player's for the run (no way back to the default place: P6o); popped back in, it returns where it was on the bench before (`ReturnPlace`). Several instruments out at normal size overlap: the places are for one at a time.
- A press on a window's close button is not a click on the window: ImGui closes at the release, a frame later, and counting the press would take the focus from the tool that has it (`InstrumentClicked`).
- ImGui default fonts (vector and bitmap) lack `–`/`—`, `−`, `Δ`, `◀`: use `Displayable`, ASCII `-`, `dt`, and draw arrows as triangles. They have `µ`, `·`, `×`.
- The agent can't see the live screen: use `bw_ui … --screenshot X.png --after 1s` (release build) and view the PNG. The analyzer opens at its first view (10 sample points per division about the Trigger: bus values readable at 100 ns); `--view 1us:+5us`, `--marker +2us`, `--cursor +3.7us` set the rest. At `2us` a 1 µs bus cycle is too narrow for its text in the default window.
- Window input: read pan and zoom once per frame before drawing anything that depends on the view (lanes, but also an axis or overview above them: reserve their rows, draw them after), and take the wheel with `ImGui::SetItemKeyOwner(ImGuiKey_MouseWheelY)` and `ImGuiKey_MouseWheelX` so zooming never scrolls the window (P3c's intermittent navigation bugs). Trackpad wheels are fractional: step on whole notches (`WheelNotches`). A drag that rounds (the scope's delay to tenths of a division) is measured from the press, or slow drags never move.
- Draw long Captures from runs (`CaptureRuns`), jumping sub-pixel runs by binary search: per-point loops over 65 536 points × 32 lanes blow the UI budget.
