# Recipe — Add a Machine

A new board on the tutorial ladder, in its own directory `machines/NNN-name/` (P6a): the netlist `<m>.bwn`, `board/` (`.place`, `.kicad_pro`, `.kicad_pcb`), `manuals/`, `docs/` (development docs, never shown to the player), `roms/`, `puzzles/` (`NN-name.bwp`, easiest first). `<m>` is the Machine's name in each Puzzle's `machine` line; the number orders the directories and is dropped when shown. The layout and its loading rules: [MACHINE_DIRECTORIES.md](../p6a-machine-directories/MACHINE_DIRECTORIES.md). New Parts first ([ADD_PART.md](ADD_PART.md), [ADD_BOARD_DEVICE.md](ADD_BOARD_DEVICE.md)); Puzzles last ([ADD_PUZZLE.md](ADD_PUZZLE.md)).

## Order

1. **Docs**: `machines/NNN-name/docs/NAME.md` (what it does, circuit, Puzzles) and `NAME_DESIGN.md` (netlist, Board notes, Puzzles with exact faults, manuals). No code design needed unless new Parts.
2. **Netlist + manuals + fault-free test** (headless, one commit).
3. **Board**: the agent places it with `bw place`, the user routes it in KiCad, the agent wires the tests (one commit).
4. **Puzzles** (needs the Board for cracks).
5. **Session test + release check**, then the docs rows.

## 2. Netlist, manuals, fault-free test

- `machines/NNN-name/<m>.bwn`:
  - header comment: Machine number, spec path, one-paragraph circuit summary;
  - `part REF TYPE [param=value]` (types from `src/parts/catalogue.cpp`; `OSC freq=1MHz`, `R value=330`); `part J1 POWER` always (joins `VCC`/`GND`); `part J2 VIDEO` for TV Machines (the Session adds the TV by itself);
  - `net NAME REF.PIN …` with pin names from the datasheet; the same `net` name may repeat on several lines; rails are `VCC` and `GND`; short comments above groups;
  - ROMs: `part U14 2716 contents=roms/<m>.rom`, the contents file in the Machine's `roms/` (relative to the netlist's directory; a ROM two Machines use is copied into each, as the 2513's);
  - a program: `roms/<m>.asm` in the Machine's directory (header comment: Machine, spec path, memory map; syntax of both CPUs in `src/asm/assembler.hpp`; a Z80 program starts with `.cpu z80`, as `bench/bus_load_z80.asm`), then `./build/release/src/cli/bw asm machines/NNN-name/roms/<m>.asm -o machines/NNN-name/roms/<m>.rom`; commit both. `asm: every ROM program matches its committed .rom` and the ctest `asm_<m>` fail when they disagree. Let the test read the vectors from the `.rom` (`ReadRomContents`) rather than hard-code addresses; a 6502 label named `a`, `x` or `y` reads as a register, and a Z80 one named like a register or condition (`C`, `HL`, `P`) reads as one when it is the whole operand;
  - a ROM with entry points at fixed addresses (the BW-1's, `machines/120-bw1/roms/bw1_002.asm`): one `.org` each, the assembler's `$XXXX written twice` catching code that runs into the next, and a test of the opcode at each; `.checksum` for a ROM that a self-test sums (one byte making it sum to 0); local labels must differ within a label's scope (`@d1` … `@d6` for repeated inline code);
  - a program can be tested before its netlist exists, on `Mos6502Core` with the machine around it modelled in the test (`tests/machines/bw1_model`: memory map, ports, keypad, digits, NMI): seconds of simulated time in a fraction of a second; the netlist step then runs it on the real Parts;
  - firmware over several ROM chips (the BW-2001's, P5p): one `.asm` a function (`machines/130-bw2001/roms/bw2001_basic.asm`, `_edit`, `_kernel`), each `.include "bw2001.inc"` for the shared RAM map and the entry-point table (each entry a `JMP` at a fixed `.org`, the only way one ROM reaches another); one `.checksum BASE, SIZE` a chip, at its last byte, so a self-test can name the chip; in the netlist one `.rom` fills several sockets with `offset=` (`contents=../../roms/bw2001_kernel.rom offset=$800`). An included file is not `.asm`, so the `asm_*` glob leaves it alone, and the committed `.rom` changes when it does. Code that grows past a chip runs into the next chip's checksum byte: `$C7FF written twice` says where to put a `.org` for the next chip;
  - a local label's scope ends at the next global label: a `@label` branched to across one is "undefined" (rename it global);
  - one harness for a model and a netlist (`tests/machines/bw2001_harness`): a small target interface (run, a key, a RAM byte, a screen byte) that both implement, and the key presses and session runner written once. Netlist cases that would take hours in debug (the BW-2001's 2,900 typed keys) go behind `#ifndef NDEBUG` → `SKIP` and run in the release fence;
  - references: `U` chips, `R` resistors, `D` LEDs, `DS` digits, `SW` buttons, `X` oscillator, `J` connectors.
- `machines/NNN-name/manuals/user.md`, written to STYLE's Manuals rules (P6i; the Counter's is the model): `# Name` then `## What it does`: a welcome, what the Machine is and what it does (the player connects nothing: no hookup steps), and how to run a built-in test if it has one (BW-1's self-test); `## Using it` where there is something to operate (a button, a knob, a keyboard or keypad: the only optional section); `## How it works`: the circuit's story, goal first, blocks in the order the signals flow; a big Machine's parts as bold lead-ins after a short list (the binder's Markdown has no `###` and no fenced code). Backticked references must exist. The checks require the sections in this order (P6k).
- `machines/NNN-name/manuals/service.md`: `# Name — Service Manual` then `## Components`: one bullet per reference, every Part, netlist order: `` - `U1` short role: detail with `NET` names ``; then `## Test points` (a table: where to probe, what a working board shows; each reading checked with `bw run --probe` at several times, a slow Net changing between them) (a TV or computer Machine adds logic analyzer or oscilloscope setups: the pins to clip, the trigger edge, the sample time, the time per division, and what a working board shows, each checked with `bw_ui --clip … --screenshot` and the picture viewed) and `## Troubleshooting` (general charts by symptom, ordered checks, written from the working board: never naming a fault, never a Puzzle's symptom as such), both required (P6k). The Machine design's `## Manuals` says what each section holds and how the readings were checked (the Counter's is the model). Write addresses as plain `$F800`, not in backticks: a backticked `F800` reads as an unknown reference. Codes like `PA55` plain too, in either manual.
- `tests/machines/<m>_test.cpp` (add to `tests/CMakeLists.txt`): `FaultFree()` = `LoadNetlistMachine(test::NetlistPath("<m>"))` (repository paths by name: `tests/paths.hpp`); `Record(machine, end, names)` = `machine.build()` + `Simulator` + `powerOn(1)`; check the visible behaviour after settling. Tag `[machines][slow]` if it simulates more than ~1 s. Copy `tests/machines/chaser_test.cpp`.
- A big Machine (070): grow the netlist in stages, each one a commit with its own picture cases, earlier cases kept green. Tie the unused gates of each stage's chips. Measure release headless speed (`bw run … --time 2s`) at every stage. A slow drop points at a signal switching every dot across the screen; gate it to where it is needed.
- Add the Machine to the list in `tests/machines/manuals_test.cpp` (`every Machine's manuals pass their checks`).

- **A real board from its schematic** (the BW-2001, P5q): transcribe each sheet into a `.bwn` draft with a notes file (every chip's pins, the connectors, how the sheet works, the uncertain readings with coordinates) — sheets in parallel by agents, each given the project's pin names (`datasheets/`) and Net-naming rules; keep the drafts and notes with the Machine (`machines/NNN-name/docs/schematic/`). Join the sheets by Net name with stand-ins for the missing Parts and run a reference ROM on them before designing: it settles most uncertain readings at once. The netlist is then generated from the drafts by a script applying the Machine design's changes table (renames, Parts replaced, pull-up Nets as `R` Parts, stage ties); the netlist's header names its sources. A Net name shared by two sheets with two meanings (sheet 1's `RW_E_N` and sheet 2's local one) is the trap.
- A Machine copying a real board keeps every chip location of the original, even a socket its firmware leaves unused (fit it with an empty ROM, `machines/130-bw2001/roms/empty.rom`): the real ROMs need it, and the Board's layout is the board's (P5q left `UH2`, `UH6` out and P5q2 put them back).
- Running a Machine on other ROMs: `--roms DIR` (`bw run`, `bw_ui`), a file per socket named by its reference (`UH1.bin` or `UH1.rom`); the tests make such a directory of links (`tests/machines/bw2001_test.cpp`, `Basic1Circuit`).
- Stages of a real board: the first stage the part that works alone (the video), with the rest held still by ties on its inputs (an inverter's input tied rather than its output's Net grounded), each later stage removing them; a stage's case runs long enough for its counters to fall into step (the TV locks about 100 ms after power-on).
- A test ROM that needs a shipped ROM's data (a character set): `.incbin "file", OFFSET, LENGTH` (`machines/140-bw80/roms/bw80_test.asm` takes the ZX80's glyphs from `machines/140-bw80/roms/zx80_ic2.bin`); run it in the socket through `--roms`.
- A Machine without a Board yet (the BW-80 before P5x): its tests build the netlist as `bw_ui`'s no-Board branch does (`ParseNetlist`, `ResolveContentsPaths`, `ApplyRomDirectory`, `BuildCircuit`: `tests/machines/bw80_test.cpp`); the TV's page helpers are in `tests/machines/tv_page.hpp`. The TV draws without blanking: check a picture inside its page area and the margins, not over the whole frame (the sync periods show there).
- A TV Machine leaves room for the monitor (P6n): its sync sits early in the blanking, decoded from the counters there, not on their last values. Sync plus back porch 10–14 µs before the first dot, the last dot before 62 µs after the sync edge (P6f's window, TV columns 80–496), and the vertical sync at least 28 lines before the picture's first. Its fault-free case checks the lit part of a frame with `LitBounds` and `InsideWindow` (`tests/machines/tv_window.hpp`).
- Datasheet maximums can be too slow for a real board's critical path: when a fault-free case shows a systematic miss (every 64th character cell, at the address counter's longest ripple), the real board used faster parts; give them as a grade (`2114 access=300ns`) and say so. A mutation case with the slow grade shows the margin is real (the BW-80's IC4, `bw80: a 450 ns RAM misses the NOP`).
- A test of "no snow" or any rare event during a long run reads its Nets' samples each slice before `trimRecordings` (`SnowWatch` in `tests/machines/bw2001_test.cpp`), and also counts the events it watches (a zero proves nothing if the watch sees nothing).

## 3. Board (user + agent)

- A real board whose chips are named by their grid location (the PET's `UF3`): `grid pet` puts each at its cell (columns J to A left to right, rows 9 to 1 back to front, as the PET 2001's board: P5q1), lying horizontally, columns as wide as their longest chip; `upright REF up|down|in [0|180]` stands a chip as the real board does, reaching into the empty rows above or below (a row counts as reached past the 2 mm part gap: snapping crosses edges by less); take the layout from a drawing or photo of the real board (P5q1: PET-Shack's component layout), not from the reference's letters alone; `next` may name a grid chip (chain a row of resistors: `next R29 R28 right`; a long chain starts in the middle and goes both ways); parts with no rule go to the empty cells nearest their Nets; headers on the back and front edges lie along them.
- A real board with a drawing and a hole table (the ZX80 issue 2, Searle's foils: P5x): `size W H` (mm, the outline) and `at REF X Y [ANGLE]` (mm from the back-left corner, the courtyard's centre; ANGLE KiCad's 0, 90 or 180, upright by default, P6n) put every chip where the board has it (the DIP centres from the hole rows; y flipped when the table counts from the front); connectors by `edge`, passives by `next` beside their chips, the rest free (nearest its Nets). A `next` chain that runs into a chip or off the Board is refused by name: shorten it or start it elsewhere. A 2 × N header standing for a two-sided edge connector keeps each upper contact opposite its lower (pad 2n − 1 upper n, pad 2n lower n). `bw_ui` refuses an unrouted Board (open Nets): to look at a placement, `kicad-cli pcb export svg` and `qlmanage -t` on the SVG.
- Agent: write `machines/NNN-name/board/<m>.place` from the Machine design's panel parts (connectors, LEDs, digits, buttons and the resistors beside them; grammar in [BOARD_PLACEMENT.md](../p4k-board-placement/BOARD_PLACEMENT.md#what-is-new)), then `./build/release/src/cli/bw place machines/NNN-name/<m>.bwn machines/NNN-name/board/<m>.place -o machines/NNN-name/board/<m>.kicad_pcb`. It writes the Board with every part placed (the chips annealed on wire length) and a `.kicad_pro` if there is none, and prints the wire length and the grid. The `place_drc_<m>` ctest appears by itself (reconfigure). Release takes under a second on 070; debug about 20 s.
- User: opens `<m>.kicad_pro` and routes it ([KICAD_GUIDE.md](../p2a-board-layout/KICAD_GUIDE.md) steps 7–8: F.Cu/B.Cu only, no zones, DRC 0 errors), keeping any route order a crack Puzzle needs. The user may rearrange it (110, and 120 after the KIM-1's own layout); `place_drc_<m>` keeps checking the rules' own Board. Digits must be turned 90° in KiCad (`bw place` places at 0°, where the digit footprint reads sideways). A keypad is placed with `next … back` rules, row on row (`machines/120-bw1/board/bw1.place`). On a routed Board, `bw place` refuses without `--force`.
- KiCad 10 keeps a footprint's `(point)` (the DIP centre marker on F.Fab) in Board coordinates; `bw place` before `e8dfffa` wrote it relative, which left magenta crosses away from their parts (moved back on every Board in `7c7baa6`). Close the Board in KiCad before the agent edits it: KiCad does not reload a changed file and its next save, autosave included, undoes the edit.
- **Nets changed on a routed Board, no part added** (P6n): the Board is routed again whole, its placement kept, with no human step but Freerouting. A Board with a `.place` that still gives its placement (a fixed layout: `size` and `at`), `bw place --force`; any other (laid out by hand, or tidied after `bw place`), `python3 -I tools/renet_board.py machines/NNN-name/<m>.bwn machines/NNN-name/board/<m>.kicad_pcb -o /tmp/<m>.kicad_pcb` (every footprint kept, every track and via deleted, each pad on its Net from the netlist), copied over the Board with KiCad closed. A hand-made Board without `.place` gets one first, so the next change is `bw place`: each footprint's courtyard centre and angle from the `.kicad_pcb`, as `size` plus one `at` a part (050, 060; the parts land on the 1.27 mm grid, under 0.64 mm from where they were). The user opens it, Freerouting on the whole Board, saves; `check-board` ok (leftovers to `route_missing.py`, below). Each crack Puzzle's crack moves with its Trace: its symptom case in the Machine's test, and every Repair typed with a crack's coordinates (`shorts power`'s `mend:`), checked again.
- Parts added to a routed Board: `bw export-kicad` to a scratch path, KiCad's File → Import → Netlist with its replace and delete options off (footprints match by reference and timestamp), the new parts placed and routed by the user. Connections the rerouting breaks are routed by `tools/route_missing.py` (below).
- **A few connections left unrouted** (Freerouting gave up on them, a rerouting broke them, they are too crowded to thread by hand): `python3 -I tools/route_missing.py machines/NNN-name/<m>.bwn machines/NNN-name/board/<m>.kicad_pcb -o /tmp/<m>.kicad_pcb` routes every connection `check-board` reports open, one track each (A* on a 0.1 mm grid over both layers, vias where both are free, the Board's clearances plus 0.05 mm; the goal is the Net's copper not yet joined to the starting pad, so a pair of pads already joined to each other, the BW-80's `J4` grounds, still reaches the rest), until `check-board` says ok, then runs KiCad's DRC on the copy. Look at the copy, then copy it over the Board with KiCad closed. Seconds to a minute a connection; correct, not pretty (staircases, extra vias: P5q2's `CASS_WRITE` took 10). `--step 0.05` for very tight spots. Not for a whole Board: that is Freerouting's job. It has no ctest (it was checked by hand on the BW-2001's Board, 53 s): if it ever gets one, use a small Board with one open connection (seconds), never a big Machine's: the suite is already long.
- Freerouting may leave one connection (P2a, 080: a ROM pad boxed in by its neighbours' tracks). DRC says "1 unconnected items" and `check-board` prints `open NET: …`. The agent can add it: find a free path from the tracks around it, write the segments and vias into a scratch copy of the `.kicad_pcb` (KiCad closed), and check it with `kicad-cli pcb drc` and `check-board` before copying it back.
- Agent, once it is saved: read the routing order of every Net a crack Puzzle needs (ADD_PUZZLE.md) before writing Puzzles. A "pad at an end of the route" constraint is easy to miss in KiCad (060 `V2`); a crack on a two-pad Net needs no constraint at all.
- Agent: `./build/debug/src/cli/bw check-board machines/NNN-name/<m>.bwn machines/NNN-name/board/<m>.kicad_pcb` must print `ok`. Commit only `<m>.place`, `<m>.kicad_pro` and `<m>.kicad_pcb`.
- The `drc_<m>` ctest appears by itself (glob in `tests/CMakeLists.txt`; reconfigure).
- Add `"<m>"` to the per-Machine loops:
  - `tests/board/boards_test.cpp`: a `<m> matches its netlist` case + the courtyard loop;
  - `tests/machine/electrical_test.cpp`: `uncracked board gives the design Nets`;
  - `tests/view/board_scene_test.cpp`: `outline of every Board is a rectangle`, `every Trace and via has a design Net`.
- Switch `<m>_test.cpp` to `LoadNetlistMachine` if it was using `LoadNetlistFile`. Keep the netlist (`LoadNetlistFile`) for the `loads without warnings` case and build the others from the Board (`BoardCircuit`, as in `ball_test.cpp`); seeds that a case searches still hold, hard-coded ones do not.

## 5. Session test and release check

- `tests/session/session_test.cpp`: a `[session]` case running the Machine through `Session` (cf. `session: chaser with every instrument`); this checks the `kMaxWatched` budget.
- Release: `cmake --build --preset release && build/release/src/ui/bw_ui machines/NNN-name/puzzles/<NN-one>.bwp --screenshot /tmp/<m>.png --after 1s`, attach every instrument (`--probe`, `--clip`, `--hook`, `--meter`), and check the ratio stays 1.00× and the UI time stays under ~1 ms (about 1.5 ms on the 58-chip 070 Board). View the PNG. A Machine without Puzzles runs from its netlist (`bw_ui machines/NNN-name/<m>.bwn`, the Board is found by itself). `--press` held for less than a UI frame at the very start is missed: press after 300 ms. `--after` is wall time: a Machine at 0.25× needs four times the simulated time it should reach (`--type J3:1s:…` and a screenshot of the answer: `--after 13s`).
- Docs: roadmap row in `docs/ARCHITECTURE.md` (done + date + one-line summary), user check pending until the user plays it.

## Gotchas

- A 6520's port read clears its control line's flags: on the PET, reading PIA1's port B (the keyboard columns) takes the retrace interrupt away. Read the keys only in the retrace's interrupt handler, as the PET does (P5n's bench, P5p's model probe).
- Clocks decoded from the dot counter (090 `PHI1_N`, `PHI2_N`, `ROW_CLK`): make each edge come from one signal, and check that the gating signals (`ACTIVE`, line decodes) change only while that signal holds the gate off; the delays are in `src/parts/delays.hpp`. Keep the counter's lowest bit, which changes every dot, off gates where a slower bit will do: at 4 MHz each gate on it costs several evaluations a character.
- A keyboard key written when its cell comes round (090): the `KEYBOARD strobe=` must outlast the longest wait (a frame) plus the time to re-arm, or keys are lost.
- Seeded random power-on: the fault-free test must not depend on the seed (settle first, or check every phase).
- Measure speed on an idle machine: a debug `ctest -j 12` running alongside makes a release `bw_ui` read 0.8× for a 1.00× Machine.
- Debug is about 0.07× real time (a TV Machine at 2 MHz, 0.03×): keep simulated time short, and use the release build for screenshots that show readings.
- A 74LS161's `RCO` follows `ENT` combinationally: with a decoded signal on `ENT` (a line end), `RCO` pulses for ~20 ns when the count reaches 15 before that signal falls. Never clock or clear anything from such an `RCO`; put the decoded enable on `ENP` and keep `ENT` for the carry chain (060 `VRCO`).
- A pin left out of every `net` never joins a Net, even through a Bodge Wire on its pad (`ElectricalNetlist` builds from the netlist's connections): a pad meant for a player's wire (the BW-1's strap, `U24` pad 4) gets a one-pin Net (`net STRAP U24.Y3_N`), which gives no warning.
- `--press` durations need a unit and a start after 0 (`SW1:1ms:2s`).
- Every resistor needs `value=` (ohms: `470`, `1k`, `4k7`). One between two signal Nets (the ZX80's data bus, P5u) is a series resistor: the Net that nothing else drives takes the other's value through it, and the values decide weak fights there.
- A processor Machine: a `POR` on `RES_N` (open collector, with the pull-up and the Reset button on the same Net) starts the CPU at its reset vector; without one it runs from a random state. Gates start with random outputs too, so a strobe built from them can pulse once in the first ns: count strobes only after the reset.
- Power-on draws a random bit per output and Net, and every new chip changes every seed's draws: search seeds in the test (a `FindSeed` over the state the case needs), never hard-code them.
- Picture-reading cases that simulate several seconds cost minutes in debug (070: 4–10 s each, the debug suite about 9 minutes); keep each case to what it shows.
- Board re-layouts move cracks: Puzzles use `fault crack A B N%`, so only which far pads lose the signal may change.
