## Implementation notes

- Docs review (before the docs commit), fixed: the Typewriter's Service Manual renamed in phase 1 (an `R3` left would fail the checks); every test text the required sections break listed, `kGoodService` kept and a `kServiceTail` added; ADD_MACHINE §2 changed with the checks (phase 9); the Counter-only sections case folded into the every-Machine case (sections not empty); the macOS `sed -i ''`; the Typewriter docs' lines named; `drc_typewriter` the Board's check, not `place_drc_typewriter`.
- Phase 1: `check-board` ok; release `-R "typewriter|manual"` 36 passed.
- Phase 2: each Machine drafted by a sub-agent, read whole and kept (the Chaser's, Dice's, Stopwatch's and Knob Meter's prose needed no rewrite). Readings checked with `bw run --probe` (Chaser 1–2 s, every 33 ms over one run; Dice idle and with `ROLL` held, `--press`; Stopwatch running, stopped, each button held; Knob Meter at 0 %, 47 %, 100 % around a round's start at x.x425 s) and one analyzer or scope setup each, screenshot viewed; the times are in each design doc's `## Manuals`. Release `-R "manual|chaser|dice|stopwatch|knob"` 73 passed; the Stopwatch's Service Manual viewed. Found for STYLE: a run means the whole range (a pair is "`D1` and `D7`"); a pin name shaped like a reference (the 74LS90's R01, R92) is written plain or as `U8.R01`; button legends in plain capitals (`RESET` is also a Net); the probe's P lamp holds 100 ms; readings that need input say the state ("idle", "`ROLL` held").
- From phase 3 on, the Machines of phases 3–7 were drafted at once (they share no file), the brief carrying phase 2's findings; each phase is still reviewed and committed in ladder order.
- Phase 3: readings with `bw run --probe` (Test Pattern 0.3–1.1 s; Ball 0.5–2 s, the ball's directions every 0.2 s to 3.1 s; Tennis with START pressed, 150 ms–4 s, game over at 55 s, the next START at 57 s, `--vcd` records of 8, 42 and 60 s); analyzer and scope setups for a line and a frame on each, the Ball's ball, Tennis's controllers, screenshots viewed. Every fast TV signal shows P; the tables give the level it mostly reads ("mostly H, with P lit"). Release `-R "manual|test.pattern|ball|tennis"` 71 passed; Tennis's User Manual viewed (the keys table drawn). Seen: Tennis's knobs start at 0 %, both paddles at the bottom, so a fresh game misses every serve (the user's knobs decide; not a manual matter).
- Phase 4: readings with `bw run --probe` (Message 0.5–1.5 s; Typewriter idle 1–1.5 s, CLEAR held, then `--type 'J3:1s:HI\n'` read at 1.002–1.25 s); analyzer setups: the Message's dots, a line, the two ROM lookups (codes `"HOPE"` and their dots), a frame; the Typewriter's text line, a row's top line (the page's clocks and the row buffer loading), a frame, a key written. Screenshots viewed. Both see the default TV window cut the page's left (Message, about a character and a half) and the Typewriter's top rows and left columns (so typing after CLEAR shows only in underscan): P6n's margins, not written in the manuals. The Markdown has no `###`: a big Machine's parts are bold lead-ins after a short list. A bare pin name that is not a Net (`PHI1`) is reported as an unknown reference, as R01; one that is also a Net links the Net.
- Phase 5: readings with `bw run --probe` (Heartbeat 50 ms–1.08 s, RESET held and released; LED computer 30 ms–1.5 s, RESET held 500–700 ms, the light back at `D1` at 760 ms); analyzer setups with the address bus as a group: the Heartbeat's count (139F, 13A0… a step every 2 µs), the LED computer's program starting at F800, its first RAM write, its LED write; screenshots viewed. An LED's pin 1 is its cathode: the anode is `D16.A`. A signal changing about every 125 ms makes the P lamp (100 ms) flicker; the LED computer's manual says so.
- Phase 6: readings with `bw run --probe` (idle 10 ms–2 s; ST and RS held; a `JMP` loop typed at 0200 with `--press`, running and with SST on); analyzer setups: the buses around a monitor loop (`--group U1.A0,U1.D0`), the digit scan (`PB1`–`PB4` and the segments, about 0.55 ms a digit), a key read (GO held, `PA1` low on row 2); screenshots viewed. The keypad table's header is its top row (an empty header drew an empty band; a long header cell wraps). The digit and row lines only pull low or float: the probe shows L or nothing, never P; the analyzer draws them mid-level, so the setups scan `PB1`–`PB4`. `BW1.md` corrected where the simulator disagreed: `RW` pulses while the monitor waits (its stack and ports), and a `BRK` shows its address plus 2.
- Phase 7: readings with `bw run --probe` idle at READY (0.2, 1.5, 2 s) and while typing (`--type 'J5:1.4s:…'`); `--record` VCDs for what the probe cannot show (`IRQ_N` low 72 µs a frame, `SEL8` high 2 µs every third of a second for the cursor blink, `DS1.K`'s 9 ns glitch once a frame); analyzer setups: a line, a frame, the video address counting, the 6502 starting at FFFD, the 6502 writing the screen; screenshots viewed. The analyzer re-arms at power-on only if armed: those rows say "press Arm, then switch the power off and on". The keyboard rows float between scans, so the probe shows nothing on them; the manual probes `UG8.PA0` and the `KIN` lines instead. The Markdown has no `###` and no fenced code: the three parts of How it works are bold lead-ins, the banner three code lines. `BW2001_DESIGN.md`'s Puzzles note no longer says the Service Manual has only Components.
- Phase 8: drafted alone, last (with the brief's every finding), read whole and kept. Readings with `bw run --probe` (0.5 ms–1 s; a key held with `--type J3:300ms:O`, read at 330 and 345 ms) and `--vcd` for timings (the picture from 172 ms, the line sync 6.1 µs every 63.7 µs, the frame sync 386 µs every 19.7 ms, nine keyboard reads 25 µs apart); analyzer setups: a line and its sync, a character drawn (the forced NOP, the latch, the load, the shift), the character shapes (the ROM address F80 after the cursor's B0), the frame sync, the keyboard rows; screenshots viewed. The analyzer arms at power-on and the start-up fires most edges at once: each setup triggers on something only the running picture makes (`M1_N` rising with `NOP_EN` high). The `J2` bullet corrected: `VIDEO` is high for white. Seen, not written in the manuals: the working Machine's TV shows a dashed line along the cursor's row (in `bw_ui` and `bw run --tv`); a real ZX80 shows only the K. For the user.
- Phase 9: `CheckShape` takes `SectionRule`s (a name, optional or not), the message `What it does[, Using it], How it works`; the Counter-only case folded into the every-Machine case (each required section not empty, `Using it` when present). Release `-R manual` 16 passed; debug `-R manual` 16 passed; full release suite 1457 passed (79 s). ADD_MACHINE §2: the sections required, analyzer setups, general charts, the binder's Markdown without `###` or fenced code.
