# UI Usability — Specification (P3a)

First P3 milestone (see [ARCHITECTURE.md](../ARCHITECTURE.md), Roadmap). The P2 first playable works but is hard to use: the player has to know what to do already, does not know what the Board or a chip is for (`U6`, `74LS20`), finds pins by hovering pad after pad, clicks pins and Traces precisely, and the controls sit in one undivided column. P3a fixes that before the P3 instruments are built on the same UI. Builds on [BOARD_VIEW.md](../p2f-board-view/BOARD_VIEW.md), [BOARD_PROBE.md](../p2g-board-probe/BOARD_PROBE.md) and [BOARD_REPAIR.md](../p2h-board-repair/BOARD_REPAIR.md).

Terminology: [GLOSSARY.md](../GLOSSARY.md).

## Decisions

- **The player always knows the goal**: each Puzzle has a Brief (title and Symptom), and each Machine a User Manual saying what it does when it works. No Golden Picture: not every Machine has a TV, and words work for all of them.
- **Two manuals, like real machines**: the User Manual (owner's: what it does, how to use it) and the Service Manual (repairer's: how it works, Component roles, Troubleshooting). Separate so the start is not overwhelming, and so a later hard mode can withhold the Service Manual (not in P3a).
- **The player always knows the state**: one banner says whether the power is on or off, which tool is active and what that tool does now.
- **The Board explains itself**: the Service Manual gives the theory of operation and the role of every Component (`U6: end-of-frame decoder`). A simplified Datasheet per Part says what the chip is and what each pin does. Pin names appear on the Board when zoomed in.
- **Troubleshooting is authored, not generated by the game**: the Service Manual may have a Troubleshooting section (what to measure, what it means). It is hidden unless the player opens it (an easy mode). Having the game generate it from the netlist is out of scope.
- **Manuals and Datasheets are data files**, authored by the user or the agent in a small Markdown subset (the agent reads the netlist and runs the Golden Machine for real figures), reviewed by the user, checked headlessly against the netlist and the Parts catalogue.
- **Tool modes stay** (Probe / Swap / Mend). The fix is a clearer layout: a toolbar above the Board for everything that acts on the Board, and labelled sections in the right column.
- **Probing stays on the Board.** Clicking a pin in the pinout highlights and frames its pad, but does not probe it.
- **No new leaks.** Brief, manuals, Datasheets and pin names come from the design Netlist, the Parts catalogue and authored files, never from Faults. A Brief describes the Symptom, never the Fault.
- **Look and feel are first guesses**, tuned once played. The spec only fixes what the tests check.

## Scope

In: Brief in `.bwp`; User and Service Manuals for `counter` and `test_pattern`; Datasheets for every catalogue Part; state banner, toolbar, grouped right column; Chip panel; pin names on the Board; larger snapping for pads, Traces and vias; navigation additions; hidden debug stats.

Out (later P3 milestones fix these): Schematic (P3b), new instruments (P3c, P3d), new Repairs (P3e), "is it fixed?" check (P3f). Also out: hard mode, generated troubleshooting, settings persistence, tutorials, sound. The counter Board's lack of an output connector is P3d's (it gets one for the Oscilloscope).

## Behaviour

### S1 Brief

- `.bwp` gains two optional lines: `title "Dead counter"` and `brief "The bottom of the picture is missing and the rest rolls."`. Double-quoted, one line each, at most once. If they are missing, the title is the file stem and the brief is empty.
- The three existing Puzzles get a title and a brief written from their Symptoms (checked on the TV), not their Faults. The dev comment stays.
- `bw_ui` shows the title in the window title (`Bodgewire — Dead counter`) and the Brief at the top of the right column. `bw run` ignores both.

### S2 Manuals

- Two files per Machine, next to `netlists/`: `manuals/<machine>/user.md` and `manuals/<machine>/service.md`. Both optional: a missing one shows `no user manual` / `no service manual`.
- Markdown subset: `#`/`##` headings, paragraphs, `-` bullets, `` `code` ``, `**bold**`. Anything else is shown as plain text.
- User Manual, fixed sections in this order:
  - `# <Machine title>`;
  - `## What it does`: the working behaviour as the player observes it (outputs, picture, frequencies);
  - `## Connections`: each connector and what goes on it (power, video, outputs).
- Service Manual, fixed sections in this order:
  - `# <Machine title> — Service Manual`;
  - `## How it works`: theory of operation in a few paragraphs, by functional block (clock, horizontal counter, ...);
  - `## Components`: one bullet per Component, `` - `U6` end-of-frame decoder: ... ``;
  - `## Troubleshooting` (optional): bullets like ``check `U1` pin 15 (RCO): a pulse every 16 µs. If missing, the fault is in the clock or `U1`.``
- Each opens in its own window from the toolbar (User Manual `U`, Service Manual `H`), with headings collapsible. `Troubleshooting` is collapsed with the label `Troubleshooting (easy mode)`.
- References in backticks (`` `U6` ``, `` `U1` pin 15 ``) are links: hovering highlights the Component or pad on the Board, clicking frames it (S8).

### S3 Datasheets

- One file per Part, `datasheets/<Part>.md` (`datasheets/74LS20.md`), same Markdown subset.
- Sections: `# 74LS20 — dual 4-input NAND`; `## Function`: what it does in one or two short paragraphs, plus a truth table or a counting/timing rule where it helps; `## Pins`: one bullet per distinct pin name, `` - `1A`–`1D`: inputs of gate 1 ``, `` - `CLR`: clear, active low ``; power and no-connect pins included.
- Connectors and the crystal have Datasheets too, so every Component can be explained the same way.

### S4 State banner

- One line across the top of the window, always visible:
  - power: a large `POWER ON` (green) or `POWER OFF` (grey), plus `paused` when paused;
  - active tool and what a click does now: `Probe: click a pin or trace`, `Swap: click a chip`, `Mend: click a crack`;
  - when the tool cannot act: `Swap: power off first` and `Mend: power off first`, shown in amber.
- Clicking with a tool that cannot act flashes the banner amber, so the click is not silently ignored.

### S5 Layout

- **Toolbar** above the Board panel: Power, Pause, Speed (`1×` / `Max`), then tools (Probe P, Swap S, Mend M) as large toggle buttons with their keys shown, then Layer (F.Cu / B.Cu, L), Fit (F), User Manual (U) and Service Manual (H).
- **Right column**, top to bottom, each a collapsible section with a header: `Puzzle` (title, Brief, and the User Manual's `What it does`), `TV`, `Probe` (lamps + probed pin as `U1 pin 13 QA · H0`, or `not probing`), `Chip` (S6), `Repairs` (log).
- **Debug stats** (`t`, speed ratio, lock, ring wait, ui ms) and Seed move into a `Debug` section, collapsed by default. Seed only takes effect at power-on, as now.
- Default window stays 1280 × 800.

### S6 Chip panel

- Shows the hovered Component, or the selected one when nothing is hovered. A Component is selected by clicking it (any tool) or one of its pads, and stays selected until another is.
- Contents, top to bottom:
  - `U6 · 74LS20 · dual 4-input NAND`;
  - its role from the Service Manual's `Components` (`end-of-frame decoder: ...`), when there is one;
  - a pinout: a DIP outline with pin numbers and names on both sides, pin 1 marked, power pins greyed; for each pin, the design Net it is on (`H0`);
  - the Datasheet's `Function`, collapsible, then its `Pins`.
- Hovering a pin in the pinout shows its Datasheet line and highlights the pad and its design Net on the Board. Clicking it frames the pad and flashes it. It does not probe.
- The hover tooltip on the Board adds the role: `U6 74LS20 · end-of-frame decoder`; on a pad, the pin's Datasheet line: `U6 pin 6 1Y · VEND_N — output of gate 1`.

### S7 Pin names and labels on the Board

- Fitted view: each Chip shows its reference and Part (`U3` and `74LS161` under it) inside the courtyard.
- When a pad is at least ~14 px wide, its pin name (`QA`, `CLK`, `VCC`) is drawn next to it, outside the courtyard.

### S8 Snapping

- Hover and click use the same pick, so what is highlighted is what a click acts on.
- Pads: the nearest pad within 12 screen pixels or half the pin pitch, whichever is larger, wins over everything else.
- Otherwise vias, then Traces: the nearest within 10 screen pixels of its copper edge (not its centreline). A thin Trace is as easy to hit as a wide one.
- Layers: the Active Layer wins when both Layers have a Trace in range; when it has none, the other Layer's Trace is picked. Hover, probe and Mend then act on the picked Trace's Layer (a crack on B.Cu can be mended with F.Cu active). The Active Layer stays the one drawn on top and the tie-breaker.
- Otherwise the Component under the cursor (courtyard), as in P2f.
- The probe tip stays on the probed point until another probe click. Clicking empty board does not unprobe; `Esc` does.
- "Frames" (S2, S6): pans and zooms so the target is centred at a zoom where its pads are at least 14 px.

### S9 Navigation

- Double-click a Chip: zoom so its courtyard fills about half the Board panel, centred.
- Left-drag on the Board pans once the drag passes a few pixels, so a click is still a click. Right/middle drag keep working.
- `+` / `-` zoom around the panel centre. `F` and Fit unchanged.

### S10 Checks

- Headless:
  - `.bwp` parses `title`/`brief`; rejects duplicates, a missing closing quote and unknown keywords; the three Puzzles have both;
  - User and Service Manuals of `counter` and `test_pattern`: required sections present and in order; exactly one Service Manual `Components` bullet per Component of the netlist; every backticked reference names an existing Component, and every `pin N` an existing pin;
  - Datasheets: one per catalogue Part; title matches the Part name; every pin name of the Part is covered by a `Pins` bullet (ranges like `1A`–`1D` allowed);
  - Markdown subset parser: headings, bullets, code spans, bold, unknown syntax kept as text;
  - snapping on the test-pattern Board, at the fitted zoom and at 100 px/mm: a point 0.5 mm off a pad picks that pad over a Trace underneath; between two pads, the nearer; 8 px beside a 0.2 mm Trace, that Trace; a B.Cu-only spot with F.Cu active, the B.Cu Trace; off everything, nothing.
- `--screenshot` of each Puzzle, fitted and with `--probe`, read by the agent: banner, toolbar, sections, Chip panel, labels. A `--manual user|service` option opens that window for the screenshot.
- Release: test pattern still ≈ 1.00× at `1×`; UI frame < 16 ms fitted and at full zoom with pin names.

## Done when

- S1–S10 implemented; tests pass in debug and release.
- The user plays the three Puzzles again in `bw_ui` and knows what the Board should do and what each chip is for, sees the state, and hits pins and Traces without hunting.
