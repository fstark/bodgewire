# P5c — 6502 Part

Roadmap step P5c ([ARCHITECTURE.md](../ARCHITECTURE.md#roadmap)): the NMOS 6502 as a catalogue Part, and the first Machine built on it, 100 Heartbeat ([HEARTBEAT.md](../machines/100-heartbeat/HEARTBEAT.md)). Design: [MOS6502_DESIGN.md](MOS6502_DESIGN.md). Plan: [MOS6502_PLAN.md](MOS6502_PLAN.md). Terminology: [GLOSSARY.md](../GLOSSARY.md).

## Why

The BW-1 and the BW-2001 run on a 6502 (GAME_DESIGN, Computers). ARCHITECTURE (Component models) fixes how: behavioural, cycle-exact at the Pins, per edge, never gate-level. A CPU Part is the largest model yet, and a wrong cycle shows up only as a broken Machine far away. So the instruction core is written apart from the Pins and checked against two public test suites before it drives a Board. 100 Heartbeat is the smallest Machine that shows it working: the classic "free-run" test of a new 6502 board.

## User decisions (2026-11-13)

| Question | Decision |
|---|---|
| Opcodes | all 256, as the NMOS 6502 runs them: the documented ones, the undocumented ones (the unstable ones as Tom Harte's tests record them), and JAM, which freezes the CPU until reset. A faulty bus makes a real 6502 run garbage; ours does the same |
| Test data | a subset of Tom Harte's SingleStepTests (100 cases per opcode, MIT, licence kept) is committed and runs in every ctest. A script fetches the full set (≈ 1 GB of JSON, converted) and Klaus Dormann's functional test (GPL-3.0, not committed) into a git-ignored folder; their ctest cases skip when it is missing. Both run once in this step, and the run is recorded |
| 100 Heartbeat | this step: netlist, manuals, tests, Board placed by `bw place` and routed by the user. Puzzles in their own roadmap row |
| Its display | 1 MHz; all 16 address lines through two 74LS244s to 16 LEDs; resistors hold the data bus at `$EA` (NOP) and `IRQ_N`, `NMI_N` high; a Reset button on `RES_N` |

Decided while designing (2026-11-13), for the user to overrule:

- The real MOS 6502 pinout on DIP-40 (MOS 6500 data sheet, Nov. 1985, p. 10), datasheet names: `PHI0` in, `PHI1` and `PHI2` out, `RDY`, `IRQ_N`, `NMI_N`, `SO`, `SYNC`, `RES_N`, `RW` (high read, low write), `A0`–`A15`, `D0`–`D7`, `VCC`, `GND` (pin 1) and `GND2` (pin 21, the second `VSS`), `NC1`–`NC3` (pins 5, 35, 36).
- Pin timing from the data sheet's 1 MHz table (p. 5): typical values where it gives them, maximums elsewhere (SYNC).
- Power-on: A, X, Y, S, P and PC random, the CPU at the start of an opcode fetch at that PC. A real NMOS 6502 starts in an undefined state and needs `RES_N` held low for two cycles; ours runs from wherever it lands. Heartbeat works either way: every byte it reads is a NOP.
- The pins are NMOS: `Family::Mos` (a floating input keeps its last level, X reads as a random bit).
- The data bus Nets of 100 Heartbeat are `DB0`–`DB7`, so they never read like the LEDs `D1`–`D16`.
- The LEDs light while their address line is high: each LED's anode on a 74LS244 output, its cathode through a 330 Ω resistor to `GND`. A player reads the lit LEDs as the address in binary.

## What is new

1. **Instruction core** (`Mos6502Core`). Pure C++, no simulator types: one bus cycle at a time. `bus()` gives the cycle in progress (address, read or write, data written, SYNC); `step(data)` ends it with the byte read and works out the next. Inputs: IRQ (level), NMI (edge), RES (level), SO (edge). It covers:
   - the 151 documented opcodes, with every cycle's address and R/W as on the chip: dummy reads (implied, page-crossing index, stack), the double write of read-modify-write instructions, `JMP ($xxFF)` wrapping in its page;
   - decimal mode as the NMOS 6502 does it (N, V and Z from the binary intermediate, invalid BCD digits included);
   - the 105 undocumented opcodes: the stable combinations (`SLO`, `RLA`, `SRE`, `RRA`, `SAX`, `LAX`, `DCP`, `ISC`, `ANC`, `ALR`, `ARR`, `SBX`, `SBC` `$EB`, the NOPs with their addressing), the unstable ones (`ANE`, `LXA`, `SHA`, `SHX`, `SHY`, `TAS`, `LAS`) with the constants and quirks of Harte's data, and the 12 JAMs;
   - interrupts: IRQ and NMI polled at the end of the second-to-last cycle of an instruction, a taken branch that stays in its page using the poll from the end of its first cycle (so an interrupt arriving during it waits one more instruction), NMI taking over a BRK or IRQ sequence before its vector is read, the B flag pushed set only by BRK;
   - reset: while RES is asserted the CPU reads at PC; on release it runs the 7-cycle sequence (two reads at PC, three stack reads with S decremented by 3, the vector at `$FFFC`–`$FFFD`), sets I, then fetches. A JAM is left only this way.
2. **`6502` Part** (`Mos6502`): the core behind the Pins. Woken only by `PHI0`'s edges; every other input is sampled (ADD_PART, sampled inputs).
   - `PHI0` falls: `PHI1` rises and `PHI2` falls; the cycle ends: a read cycle takes `D0`–`D7` as they were before the edge, a write releases them after the hold time; `RES_N`, `NMI_N`, `IRQ_N`, `SO` and `RDY` are sampled; the next cycle's address, `RW` and `SYNC` are driven.
   - `PHI0` rises: `PHI1` falls, `PHI2` rises; a write cycle drives `D0`–`D7`.
   - `RDY` low at the end of a read cycle repeats that cycle (the bus holds still); on a write cycle it is ignored until the next read, as on the NMOS chip (data sheet p. 7).
   - `SO`'s falling edge sets V.
   - Datasheet `datasheets/6502.md`.
3. **Test data and tools.** `tests/data/6502/`: the committed Harte subset, one text file per opcode in a compact format both test sets share, the converter (Python, run with the repo's venv) and `fetch.sh` for the full sets into `external/6502/` (git-ignored).
4. **`GND2`.** A second ground pin, for chips that have two (the 6502's two `VSS` pins): `PowerPinRail` maps it to the `GND` rail for the netlist builder (implicit power, and `net GND U1.GND2` accepted), `PowerPinVolts` gives 0 V, the catalogue test accepts it.

## Machine

100 Heartbeat, built as in [HEARTBEAT_DESIGN.md](../machines/100-heartbeat/HEARTBEAT_DESIGN.md): a 6502 free-running on NOPs, its 16 address lines on LEDs; netlist, manuals, Board placed by `bw place` and routed by the user. No Puzzles.

## Tests

- **Core, hand-written:** a NOP's two cycles; reset from any state (the bus of the 7 cycles, I set, the vector fetched); IRQ taken or masked, the poll point (an IRQ asserted in the last cycle waits for the next instruction), `CLI`/`SEI` latency, the taken-branch delay; NMI on its edge only, once per edge; NMI taking over BRK; JAM's bus and only RES leaving it; SO setting V.
- **Core, Harte subset:** for all 256 opcodes, 100 cases each: every cycle's address, data and R/W, then the registers and the RAM.
- **Core, full suites (skipped without `external/6502/`):** all 2.56 M Harte cases; Dormann's functional test from `$0400` until it traps at its success address (`$3469` in the fetched build).
- **Part:** catalogue row, pins, power and package; per `PHI0` edge, the delays of the address, `RW`, `SYNC`, `PHI1`, `PHI2` and write data against `delays::`; a read takes the data from before the edge; a write releases the bus after the hold; `RDY` low stalls a read and not a write; `RES_N`, `IRQ_N`, `NMI_N` through the pins; X on the data bus read as a random bit; no evaluation from data or input changes alone.
- **100 Heartbeat:** the netlist loads without warnings; for several seeds, the address bus counts up one every two cycles with `SYNC` on every other cycle and `RW` high throughout; `LA15` (the top LED's anode) is high for 65.536 ms of each 131.072 ms period; a Reset press makes the CPU fetch from `$EAEA` 6 cycles after the cycle that sees the release. Board checks, KiCad DRC, manuals; a Session test with every instrument attached.
- **Release:** `bw_ui` on Heartbeat with every instrument attached at 1.00×, screenshot viewed.

## Later

- Internal Fault hooks (dead IRQ logic, a stuck register bit): P5f or a Puzzle row.
- The NMOS minimum clock (50 kHz, dynamic registers losing their contents): not modelled; a stopped `PHI0` freezes the CPU as it is.
- `RDY` in the cycle a write follows (the NMOS chip's "ignored until the following read") is modelled; DMA through `RDY` is P5i's concern.
