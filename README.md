# Bodgewire

A game about fixing old digital computers, chip by chip.

All the code in this repository was generated by Claude, Anthropic's AI, with a human telling it
what to build and checking the result. If you'd rather stay away from AI-made projects, this is
the place to stop reading. No hard feelings.

Try it in your browser: [fstark.github.io/bodgewire](https://fstark.github.io/bodgewire/).
Every Machine is there, slower than the desktop build (a fast computer helps), and without the
pop-out windows. It's not really playable that way, but it gives a good idea of what the game
looks like.

## The goal

Bodgewire simulates the repair of old digital computers: late-70s and early-80s boards made of
TTL chips, up to real 8-bit computers. Every signal on the board is simulated, so a fault is a
physical thing (a cracked trace, a chip output stuck low, a solder bridge) and the symptoms come
out of the circuit on their own. Nothing is scripted. Every fault has a cause, and you can find it.

## What it is

You're at a repair bench. In front of you is a broken Machine and a post-it saying what's wrong
with it: "The LED never lights." You have the board, its manuals (a User Manual, a Service Manual,
datasheets for every chip) and a shelf of real tools and instruments. Find the fault, fix it,
power it back on.

There are 118 Puzzles on 14 Machines. The first one blinks an LED with five chips. The last two
are chip-for-chip copies of the Commodore PET 2001 and the Sinclair ZX80, running their real ROMs.

Every Machine shows up in the launcher with a short description, and each of its Puzzles is a
post-it you can pick. "Start the Machine" gives you the working one, to see how it should behave.
A Puzzle you've repaired keeps its tick on the launcher, from one launch to the next.
The last post-it, "Random fault", breaks the Machine somewhere new each time you open it, and
checks that the fault shows before handing you the bench. It can be anywhere on the board, so
they never run out: fix one and the owner's card offers you another. If one beats you, the
binder's Give up page tells you what it was.

## A repair, step by step

Here's the Counter's first Puzzle, "Dark LED".

The bench opens on the board. Five 74LS161 counters divide a 1 MHz crystal down to about one blink
a second, and the red LED `D1` on the right should be blinking. It stays dark. The tools are on
the shelf at the bottom.

![The Dark LED Puzzle on the bench](docs/readme/bench.png)

Hover a chip and its traces light up, with every pin named. On `U5`, pin 11 (`QD`) is the one that
goes to the LED.

![U5's traces and pins](docs/readme/traces.png)

So is the chip broken, or the LED, or something in between? Power off, take the multimeter, clip
its black lead on the LED's pad and hold the red one on `U5` pin 11. It shows dashes, no beep: a
trace runs from one to the other, but they aren't connected.

![The multimeter reading open between U5 and the LED](docs/readme/continuity.png)

Zoom in on that trace. About halfway along, there's a hairline crack right across the copper.

![The crack in the trace](docs/readme/crack.png)

A crack is a job for the soldering iron: click on it and a blob of solder bridges the gap. Power
back on, and the LED blinks.

![The crack mended, the LED lit](docs/readme/mended.png)

Three seconds later the owner's card says thank you, with the next Puzzle one click away, and
the post-it gets a tick. The game checks the repair itself: the Board must now build the same
circuit as the fault-free one, whichever way you fixed it.

![The owner's thank-you card over the running Board](docs/readme/repaired.png)

That one is easy. Later Puzzles hide the fault behind a TV picture that rolls, a keyboard that
types the wrong letters, or a BASIC that won't start.

## Tools and instruments

The shelf is the same on every Machine.

### Tools

- **Grease pencil**: mark the board with dots, checks and crosses, to keep track of what you've
  ruled out.
- **Chip puller**: swap a chip for a new one.
- **Soldering iron**: mend a cracked trace, resolder a chip pin.
- **Cutters**: cut a trace or a wire.
- **Bodge wire**: solder a wire between two pins.

Here the first four counters have been checked off, and the trace to the LED is the suspect:

![Pencil marks on the Counter](docs/readme/pencil.png)

### Instruments

- **Logic probe**: touch any copper and it tells you HIGH, LOW or PULSE.
- **Logic analyzer**: clip it on chip pins (its pin / bus switch takes a whole bus), set a
  trigger, and read what happened before and after it.
- **Oscilloscope**: four channels, for when the exact timing between signals matters.
- **Multimeter**: hold on copper; volts, or continuity with the power off.

The logic analyzer on the LED computer's 6502, triggered on its first instruction fetch. The
address and data buses read as values: the processor fetches its reset vector at FFFC and FFFD
(00, F8), jumps to F800 and starts running its program.

![The logic analyzer on the 6502's buses](docs/readme/analyzer.png)

The oscilloscope on the Test Pattern Generator's video output: a pulse for each of the grid's
vertical lines, then the line's sync pulse below.

![The oscilloscope on VIDEO and SYNC](docs/readme/scope.png)

### The binder

Every Machine comes with its manuals, in a binder. The aA key on its cover makes the text larger,
in three steps, and it stays that way next time. The Service Manual explains the circuit, and
every chip and signal in it is a link to the board:

![The BW-2001's Service Manual](docs/readme/binder-manual.png)

Each chip has its datasheet, with the pinout and what each pin is wired to on this board:

![The 74LS161 datasheet](docs/readme/binder-datasheet.png)

And you can look inside the memory chips: the BW-2001's ROM disassembled as 6502 code...

![The BW-2001's ROM, disassembled](docs/readme/binder-code.png)

...or its character ROM, drawn glyph by glyph:

![The BW-2001's character ROM](docs/readme/binder-glyphs.png)

### And the rest

- **The post-it** with the Puzzle's symptom.
- **The Machine's own devices**: its TV, keyboard or paddle knobs, each in a window you can pop
  out to its own window on the desktop.
- **Controls**: power, pause / slow motion (a quarter of real time) / real time / as fast as
  possible, and Reset to undo every repair (your pencil marks stay).
- **View buttons** beside the Board: fit the whole Board, switch between the real and the plain
  look, pick the copper under the chips, hold a button or key down, flip the Board over.

The faults you'll meet are cracked traces, chip outputs stuck high or low, solder bridges, bad
joints, bad memory cells, and the odd dead switch.

## The Machines

### Counter

A red LED that blinks about once a second: half a second on, half a second off. The simplest board
on the bench. 3 Puzzles.

![Counter](docs/readme/counter.png)

Seven LEDs laid out like a die face. Hold the ROLL button and it rolls; let go and it lands on a

### Test Pattern Generator

The first board that drives a TV: a white grid on black, filling the screen. 8 Puzzles.

### Bouncing Ball

The first board that moves a picture: a square ball bouncing around a box, a dashed line down the

![Bouncing Ball](docs/readme/bouncing-ball.png)

### Paddle Tennis

Two players, two paddle knobs, a court seen from above, scores at the top. You know the one.

### Message Display

A page of text on the TV, from a character ROM: the first verse of Emily Dickinson's "Hope" is the

A keyboard and a TV turned into a typewriter: what you type shows on the screen. It powers up full

### LED computer

The first real computer on the bench: a 6502, a program in an EPROM, and a light bouncing back and

### BW-1

The first computer you can program yourself, built like the KIM-1 of 1976: type a program in on

### BW-2001

A copy of the Commodore PET 2001 of 1977, chip for chip and wire for wire, with the TV as its

![BW-2001](docs/readme/bw2001.png)

A copy of the Sinclair ZX80 of 1980, chip for chip, programmed in BASIC on a TV. 15 Puzzles.

## Building it

You need git, CMake 3.28 or later, Ninja and clang: Apple's on a Mac, clang 23 on Linux. Clang is
the only compiler it's built with.

You also need a very powerful machine. Every chip is simulated signal by signal, and the big
computers are hungry: on an Apple M5 Max, the BW-2001 runs at a third of its real speed and the
BW-80 at a fifth. The small boards keep up in real time.

On a Mac:

```sh
xcode-select --install          # the compiler, if you don't have it yet
brew install cmake ninja
```

Then:

```sh
git clone https://github.com/fstark/bodgewire.git
cd bodgewire
cmake --preset release
cmake --build --preset release
build/release/src/ui/bw_ui
```

The first configure downloads SDL3, Dear ImGui and Catch2, so it needs the network once. The ROMs
the computers need are already in the repository. If you want to run the tests,
`ctest --preset release -j` takes a few minutes.

### Linux

It builds and runs on Ubuntu 24.04 with clang 23. The other things it needs:

```sh
sudo apt install git cmake ninja-build libstdc++-14-dev \
    libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxi-dev libxkbcommon-dev \
    libwayland-dev libdecor-0-dev libasound2-dev libpulse-dev
```

Tell CMake to use clang on the first configure (it remembers after that):

```sh
git clone https://github.com/fstark/bodgewire.git
cd bodgewire
CC=clang-23 CXX=clang++-23 cmake --preset release
cmake --build --preset release
build/release/src/ui/bw_ui
```

It was tried on a very slow machine, an Intel i7-6700K from 2015. The small boards still keep up,
but Paddle Tennis runs at three quarters of its real speed, the BW-2001 at an eighth and the BW-80
at a twelfth.

On a Wayland desktop it runs through XWayland, so that an object can pop out into its own window.
To run it on Wayland itself, start it with `SDL_VIDEO_DRIVER=wayland`: everything then stays
inside the main window, as on the web.

If you run the tests with a KiCad older than 8 installed (Ubuntu's own is 7), the Board checks
(`drc_*`) fail. Without KiCad they're skipped.

It's developed on macOS. Windows hasn't been tried yet.
